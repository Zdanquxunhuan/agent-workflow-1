# V9：有预算、可取消、可追踪的只读 Agent 运行链路

2026-11-04。**生产目标代码和测试设计已编写；未编译、未编写或执行测试、未迁移数据库、未部署、未调用真实模型。** 本轮沿用用户分工，后续模型负责 [测试实现与执行](testing-v9-handoff.md)。V6–V8 的待验证状态保持不变。

## 范围与执行链路

V9 覆盖 Java 单轮只读聊天和 V6 会话问答：共享请求 deadline、模型/工具次数、token 预留与费用估算预算、持久账本、默认/备用模型、异步运行、SSE 阶段进度、主动取消，以及异常收尾。复用 Spring AI 1.1.2、原 ToolRegistry、引用门禁、V6/V7/V8 来源权限；不升级框架、不执行写工具。

```text
同步 chat / conversation.messages ─┐
异步 POST agent/runs ────────────┴→ 持久 run + 用户/租户/幂等键
  → 显式传递经过验证的请求身份 → 有界执行线程
  → 上下文/记忆 → 默认模型尝试：预留 → 调用 → 结算
  → 必要时重新检查来源权限 → 最多一次备用模型尝试
  → 只读工具 / RAG / MCP → 引用、来源权限和预算校验
  → 同一事务提交 task、conversation、run 成功终态

GET runs/{id}/events → 仅阶段/状态/用量元数据；可断线重连
GET runs/{id}/result → 重新授权，读取已通过校验的最终答案
POST runs/{id}/cancel → 持久取消标记，执行线程协作停止
```

本版的流是**执行进度流**，没有逐 token 正文流。严格证据回答仍完整校验后发布，页面不能把“正在查询”标成模型首 token，也不能把传输拆片伪装成模型流式生成。模型正文流、受控重规划与业务写工作流预算不在本版。

## 入口、授权与生命周期

| API | 行为 |
| --- | --- |
| `GET /api/v1/agent/runtime` | 返回是否启用 V9、进度流模式和断连策略，不返回密钥/价格配置 |
| `POST /api/v1/agent/runs` | 必须带 `Idempotency-Key`；body 为 message、可选 conversationId、revision；202 返回 run 元数据 |
| `GET /api/v1/agent/runs?active=true` | 当前 tenant/owner 最近至多 50 个运行，便于页面重载后定位/取消 |
| `GET /api/v1/agent/runs/{id}` | 状态、task/conversation 关联、预算与已记账估算 |
| `GET /api/v1/agent/runs/{id}/events` | SSE，支持 `Last-Event-ID`；无答案、用户消息、工具正文或 bearer |
| `POST /api/v1/agent/runs/{id}/cancel` | 幂等设置取消请求；终态不倒退，返回当前元数据 |
| `GET /api/v1/agent/runs/{id}/usage` | 每次模型尝试的路由、价格版本、usage 来源与记账估算 |
| `GET /api/v1/agent/runs/{id}/result` | 仅成功运行；重新检查会话及任务来源后返回答案 |

现有 `/agent/chat` 和 `/conversations/{id}/messages` 在 V9 开启时也经过同一预算入口，避免通过旧接口绕过账本。关闭 V9 恢复原路径，不表示旧路径也有 V9 的预算保障。

run 的身份键使用区分大小写的 tenant/owner，管理员不能越权读取他人运行；会话写入仍限 owner。幂等范围为 tenant + owner + chat/具体 conversation + key，另记录请求摘要；不同 payload 重用 key 拒绝，同请求不会重复派发付费调用。单轮聊天用 run ID 派生内部 task 幂等键，避免与历史接口键混淆。同步成功重试仍走原入口的来源重授权。

状态为 QUEUED、RUNNING、SUCCEEDED、FAILED、CANCELLED、EXPIRED、INTERRUPTED。`cancel_requested` 是独立标记，不代表供应商已经停止。默认每用户最多 2 个有效排队/执行 run，每实例 4 个异步执行线程 + 8 个排队位置，另限 4 个同步请求。排队时间计入 deadline；失败过载请求不会自动换一个 key 重试。

异步 worker 显式安装当前经过验证的 JwtAuthenticationToken，结束时清理 SecurityContext 和 RunScope。身份只存在于内存，不写数据库、不交给全局 inheritable thread-local；原始 token 到期后停止。运行不能在进程重启后凭空恢复用户身份，所以不会自动恢复模型调用。部署方仍负责 issuer 的撤销/短期 token 策略，不能把本地过期检查说成实时 IdP token introspection。

## 预算与账本

数据库迁移为 [V11](../../src/main/resources/db/migration/V11__agent_runtime.sql)，新增 `agent_runs`、`agent_model_attempts`、`agent_runtime_wallets` 和 `agent_run_events`。应用版本 V9 与迁移编号 V11 不同。

每次模型请求必须先在 MySQL 事务中预留，默认和备用尝试都算一次。锁顺序为用户日钱包 → run → attempt；同一用户的并发请求共享日额度，不能各自读取余额后同时透支预留。请求最多 6 次模型尝试、8 次工具调用；既有 4 轮工具循环上限继续有效。对失败/取消/未知用量也保留账本，不只记录成功回答。

价格由部署方明确填写，单位是配置币种/百万 tokens；输入、输出分别定价，记录价格版本与每次尝试的价格快照。金额用整数百万分之一币种保存，向上取整；不同币种不做隐式汇率换算。同一用户钱包按 **run 创建时的 UTC 日期** 归属，晚到结算仍回原日期。

| 数据 | 含义 |
| --- | --- |
| reserved_input / reserved_output | 调用前的保守输入估算和配置的最大输出 tokens |
| input_tokens / output_tokens | 只有供应商提供有效 usage 时填写，缺失保留 null |
| usage_source | `provider` 或 `unknown`，不是把本地字符估算冒充真实用量 |
| reserved_micros | 正在进行的尝试预留费用估算 |
| accounted_micros | 根据配置价格、供应商 usage 或保守预留计算的记账估算，不是供应商最终账单 |

输入预留使用序列化消息/工具的 UTF-8 字节数加固定开销，不依赖新增 tokenizer。它是保守启发式，**不是对所有供应商 tokenizer 的数学上界**。供应商 usage 缺失、超时或断连时，保守消耗整份预留而不是记零；正常已知 usage 则结算并释放差额。实际 usage 超过预留时如实记入，随后拒绝继续调用/发布超预算结果，不能声称已发生的供应商费用可以撤回。

因此预算是调用准入与保守记账控制，不是供应商账单的绝对硬封顶。部署还应配置供应商侧额度。价格未解析、凭据未设置、允许租户为空时启用 V9 会启动失败；不会偷偷采用网上价格或“费用为零”的默认值。当天钱包额度在多个实例配置不一致时取更严格值；提高额度需统一变更并由运营明确处理，不能依赖混合配置绕过限额。

本账本覆盖 V9 Java 问答链路的生成模型。RAG 的独立生成接口、embedding/rerank 服务、后台记忆索引和旧业务写计划生成不在这份费用账本内；这些服务也有成本，但不能因缺少 usage 就算成已覆盖。V9 在当前请求内会控制 RAG/MCP/记忆召回的等待时间和后续调用。

## 路由和取消

所有模型轮先用已配置的默认模型；仅网络/可重试服务故障、429 或单次模型超时允许切换到一个备用模型，**整份 run 最多一次切换**。不额外进行“让另一个模型判断应该用哪个模型”的付费请求。

备用模型需单独配置 endpoint、key、model、tenant 允许列表和价格版本，并支持现有工具 schema 与 JSON 输出契约。不支持的租户不外发；鉴权拒绝、非法参数、格式/引用错误、证据不足、预算耗尽、取消不触发模型切换。切换前重新校验会话/记忆/知识/MCP 来源权限，避免等待主模型期间撤权后又把旧数据发给备用模型。传输不跟随重定向，不输出供应商原始错误正文。

模型切换只重做该次模型请求，历史工具结果继续留在消息中，执行器不会因切换而重新运行已完成工具。V9 注册表路径还明确拒绝写工具，现有审批退款路径保持独立。

默认 run deadline 60 秒，单次模型最多 20 秒；所有模型尝试、RAG、MCP 和同步记忆索引等待取各自上限与 run 剩余时间的较小值。网络 future 等待中每约 200ms 检查取消/过期并取消本地等待；完整模型响应上限 1 MiB，请求正文上限 512 KiB。Java JDBC 仍受连接池获取超时、SQL query timeout 和事务 timeout 约束，非可抢占 CPU/SQL 段在检查点停止，不能宣称每个线程都在第 60.000 秒被强制终止。

答案发布时锁定 run，重新检查取消、deadline、预算与未结算预留，task 成功、conversation CAS 和 run 成功加入同一数据库事务。取消先获得状态控制则不提交答案；提交先完成则成功终态保留，后来的取消不撤销已完成答案。来源权限在生成前、切换前、回答校验及再次读取时检查；已发送到用户的数据无法追溯撤回。

SSE 断连只结束观察，不直接取消业务执行，避免短暂断网触发重复提交。客户端重连携带最后事件 ID；主动“取消”才写取消标记，run deadline 始终限制后台存活。取消本地请求不保证供应商立即停止计费。旧会话取消入口也会通知对应 V9 run；删除/改变会话仍通过已有 CAS/来源检查阻止旧答案提交。

## 故障收尾与观测

超期扫描每 5 秒处理至多 50 个 run：未结束的模型尝试按 unknown 结算，未完成 run 结束；关联 task 和 RUNNING 会话占位按身份、turn key 和 task ID 校验后标失败。收尾失败会留标记重试，不能静默丢预留。崩溃后不自动重发模型/业务请求；需要新用户请求和新 key。后台任务失败日志不带输入内容、密钥或原始供应商异常。

SSE 使用独立的 8 线程有界观察池，不占模型执行池；单次订阅最长约 60 秒、5 秒心跳，客户端可续订，前端最多尝试三次进度连接后改为有界状态轮询。服务端按数据库游标重放阶段元数据，最终结果总是通过授权 API 读取。页面令牌仍只存在内存，切换身份会清空显示并中止旧观察连接。

可统计排队等待、各模型尝试耗时、工具阶段耗时、答案校验完成时间、总运行时长、切换原因、已知/未知 usage 比例、预算拒绝及取消/过期数。页面使用浏览器单调时钟展示从提交到首次进度、校验后答案的耗时；没有收到 SSE 事件时标“未采集”，不拿状态轮询时间冒充进度时间。客户端显示时间与服务端 event 写入时间分开。本版没有模型正文流，**不提供真实模型首 token 时延指标**，没有通过运行记录证明延迟降低或费用节省。

建议告警：STARTED attempt 超期、长期未清理失败 run、余额预留未结算、日额度异常、unknown 比例、备用模型切换比例、持续 RUN_BUSY、数据库锁/池耗尽。元数据留存按组织策略归档，尝试和 run/event 必须协调清理；不得直接把未知用量改零以释放预算。应用没有自带“退款预算”接口。

## 配置与部署交接

1. 按 [配置模板](../../deploy/runtime.env.example) 设置 `AGENT_RUNTIME_ENABLED=true`、JDBC、Spring AI 网关、允许租户、显式价格和请求/日预算；默认功能关闭。备用模型独立开关与配置，不能只填一个模型名字。
2. 先在隔离验证库执行 V11 迁移；本轮没有执行任何迁移。运行账户需要新表的 SELECT/INSERT/UPDATE，DDL 由迁移账户处理，不给模型服务数据库权限。
3. 生产使用现有 `prod` 身份门槛、HTTPS 和 `MYSQL_URL` 的 `sslMode=VERIFY_IDENTITY`。运行恢复的 stale 阈值必须大于 V9 deadline 加 5 秒，避免旧恢复器抢占活跃请求。
4. 数据库连接池模板为 20；根据执行、来源校验、审计与观察请求的同时用量配置。设置并验证 Connector/J socket timeout、连接池获取超时及代理请求速率限制，避免把本地线程上限当全局容量证明。
5. SSE 代理禁用响应缓冲，允许心跳，配置连接/写超时；凭据放 Authorization header，不放 URL。接口返回 no-store，页面使用 fetch 读取 SSE 以支持 bearer header。
6. 多实例共享同一数据库、价格/币种/租户策略和 NTP 时钟；run 由接收实例执行，其他实例可观察/取消，重启不自动接管调用。发布先停止接收、等待活跃请求有界结束；强制退出由超期收尾处理。

当前没有部署验证、吞吐数据、企业备用模型准入或真实费用核对证据。交付目标是让后续模型用很少的高风险场景确认代码行为，再形成可演示的“查询 → 进度 → 工具 → 核验 → 费用记录 / 取消”闭环。
