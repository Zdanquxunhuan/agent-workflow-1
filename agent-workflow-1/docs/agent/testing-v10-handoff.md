# V10 测试架构与最小用例交接

2026-11-05：仅测试设计，**没有新增测试代码，没有编译或实际测试结果**。用户将实现与执行交给其他模型。目标是少量高价值证据；默认零真实模型、零真实支付/物流、零真实 IdP 外发。不要为了覆盖率复制实现或扩大到全库压测。

## 验证架构

沿用项目 Java17 / Spring Boot / Spring AI 锁定依赖，先由接手者做一次必要编译；不升级库解决未知问题。集成测试用隔离 MySQL8 的真实事务、外键与行锁，应用到 V12；不以 H2 或纯 mock 替代并发/暂停原子性。业务使用已有合成 ORD-1001 与本地 sandbox。

本地可编排的 Chat Completions HTTP stub 通过真实 Spring AI 适配器返回单工具响应和 usage；分别模拟 `agent_clarify`、order_query、knowledge_search、带真实 fixture 引用的最终 JSON。允许非生产环境显式 local HTTP 开关。RAG/MCP 用本地可撤权 fixture，保留真实服务端来源校验边界；若已有 V8 fixture 可复用，不重新搭一套完整外部系统。

纯策略层只覆盖参数、重复动作、错误分类。事务层覆盖暂停、并发恢复、取消、结算。HTTP 层覆盖 owner/JWT/DTO；页面只做一条人工流程或轻量浏览器冒烟。使用可控 latch/屏障触发竞争，数据库修改隔离 fixture 的到期时间来触发收尾，不等待 15/30 分钟；不要靠连续 sleep 反复轮询。

## 必需场景（8 组，小样本）

| 组 | 设计与断言 | 建议证据 |
| --- | --- | --- |
| T1 缺参闭环 | 无编号请求 → 单次 clarify → WAITING_INPUT；run 和 task 同时等待，0 个业务工具调用、0 个在途 attempt；新身份补 ORD-1001 → 新业务/知识查询 → 校验答案。run/task ID 不变、步骤 sequence 不重置，usage/次数累计 | 请求响应、任务/运行状态、阶段前后账本、stub 实际收到调用数 |
| T2 恢复幂等与所有权 | 两线程不同 key 同 revision 仅一个成功；同 key 同输入重放零新增付费调用；同 key 改内容、旧 revision、错误字段拒绝。另 tenant/owner 查看状态、plans、usage、result、补参、取消均不可用；JWT 过期不得排队 | 两个屏障请求结果与输入唯一约束；owner 外读取应 404 |
| T3 共享预算与时间 | 先消耗 attempt/token/费用/备用切换，再暂停恢复；剩余额度沿用原值且不自动加钱。执行累计时间包含两段排队，等待不消耗；链路 TTL/等待 TTL 到期即拒绝。变更币种后恢复拒绝；等待占用每用户 run 配额 | SQL 余额快照、模型调用计数；不需高并发或真实计费 |
| T4 白名单重规划 | 知识 NO_EVIDENCE 后改写一次成功，计划父版本连续；重复归一化参数立即拒绝；第三次可恢复失败触及最多 2 次上限；本地 NOT_FOUND 转固定模板澄清。NO_EVIDENCE→暂停→恢复只查订单不得输出最终业务政策结论 | plan_revised/plan_step、失败证据未进入 allowedSources、knowledge_required 跨暂停保留 |
| T5 必须停止 | 参数化代表错误：FORBIDDEN、MCP_NOT_FOUND、RAG/MCP 来源变更、工具超时、RUN_CANCELLED、预算耗尽、无效引用。均不触发新查询/改工具；写工具/混合批次/未知字段/猜测编号不得执行。只有 V9 允许的模型暂时失败可消耗那一次 fallback | stub 次数上限、业务写表零新增、终止原因；不为每个等价错误建昂贵 fixture |
| T6 暂停/恢复/取消竞争 | 暂停事务中注入异常，task/run/input 不能出现半提交；暂停提交后卡住旧 worker，立即恢复并让新 worker 开始，旧 worker 返回不得把新阶段标 FAILED；取消与恢复两个顺序均可解释；最终发布与取消复用 V9 一组屏障；task-only 取消入口不能绕过 run | 事务回滚快照、两个 worker 的事件顺序、仅一个终态，无晚到答案 |
| T7 重启与来源 | 等待态重启只恢复状态、不自动调用模型；新 JWT 恢复成功。排队提交后进程丢失/STARTED 调用丢失到期收尾，未知 usage 只结算一次；晚回包不能双记账。等待期间撤 RAG/MCP 授权或降角色，恢复前/工具执行前拒绝，不能重用旧证据 | 重启前后调用数、来源撤权证据、账本唯一结算、无 JWT 入库 |
| T8 页面与迁移 | V11 隔离库迁移 V12，原 V9 默认关闭/开启均可启动；V10 未配 V9 时启动拒绝；单页面完成一次无编号→补参→答案，等待不轮询。切身份/切 run 清空旧答案；丢响应用原 key 重试；刷新取待补字段；停止等待不启动模型；HTML 注入内容以文本显示 | 最少页面截图/网络记录、一次启动日志；保留迁移结果，不重复运行大套回归 |

T1 选择固定输出约 4 次 stub 模型响应（澄清、订单、政策、最终回答），不需要真实 DeepSeek。T4/T5 共享 fixture 参数化；T6 两个并发请求即可，无需压测。先实现 T1、T2、T4、T6，再补 T3/T5/T7/T8 的指定边界；不要省掉交易并发、身份隔离和预算累计。

## 需要特别观察的实现契约

- 模型每轮最多一项决策；若供应商默认并行返回多个调用，应明确失败并记录，而不是偷偷执行其中一个。提示/工具协议兼容性需后续验证。
- `agent_clarify` 是服务器识别的控制决策，不在普通 ToolRegistry 中；它消耗模型次数但不消耗业务工具次数。
- 新阶段不继承模型消息或旧引用；同一 task 的来源图仍要重授权。旧来源撤销时停止，不声称可自动丢弃不便的权限证据。
- 计划回放只返回服务端动作、原因与版本，输入原文在受限输入表，详细参数在原任务审计；SSE 无 token/资料正文。
- `execution_remaining_ms` 是暂停快照；活动时应断言 `deadline_at` 和总已用执行时间，不把未实时更新的余额误判成续费。
- 在 run 锁内提交暂停和最终答案，钱包结算保持 wallet → run → attempt 的原锁序；无外部网络在暂停/发布事务中。
- V10 新页面采用有界状态/计划轮询，SSE 仍可通过 V9 API 观察；等待态两者都停止占用观察连接。
- 同一链的 UTC 日钱包固定；改币种旧链拒绝。费用断言使用明确 fixture 价格，provider usage 与 unknown 分开，不能填入伪造“实际账单”。
