基于当前工作区（含未提交代码）的代码审查。评估时重新运行 Maven：56 个测试通过，失败、错误和跳过均为 0；已有双实例验收报告为 73/73，本次评估未重跑。25 条评估样例是离线功能回归，不能代表线上模型质量、容量和成本。

## 代码审查发现的优先问题（变更前基线）

1. **任务成功与业务成功脱节**：退款进入本地 PENDING 和命令队列后，任务就变为 SUCCEEDED；下游失败或 UNKNOWN 不回写任务。
2. **查询结果没有完整交付**：工具返回结构化数据，但普通任务步骤仅持久化结果码和描述，任务通常只返回 Workflow completed。
3. **恢复仅在启动时扫描**：无持续扫描、任务所有者、心跳和运行期接管；未达到过期阈值的遗留任务可能长期挂起。
4. **慢下游下租约存在重复投递窗口**：默认批量领取 20 条、30 秒租约、串行调用；后面的命令可能执行前就租约过期。现有报告未覆盖该慢调用场景。
5. **数据范围权限不足**：有角色校验，尚无组织、租户、负责客户的数据范围，也缺主管审批范围。
6. **真实下游尚未接入**：支付和物流使用 SandboxCommerceGateway；prod 门禁未强制禁止沙箱写入。

## 建议实施顺序与估算

1. 先完成业务结果/任务状态闭环、数据范围权限和持续恢复。
2. 第一阶段只开放真实只读业务，验证身份、权限、结果交付、脱敏、限流、基础告警、模型质量和容量。
3. 第二阶段仅灰度一种写操作，验证审批、幂等、状态查询、下游超时、进程崩溃、租约过期、数据库中断、对账和人工处置。
4. 用试点质量、容量、成本、恢复能力和业务验收决定扩大范围。

按一名熟悉项目的后端全职、已有业务 API/IdP/部署环境粗估：只读内部试点 2–4 周；一种真实写的小流量灰度累计 6–12 周。不含外部协调等待和完整客服前端；正式生产不按固定代码完成率判断。

## 本轮用户授权的实现范围

用户要求记录上述评估，并完成本地 Docker 数据库、合成业务数据、真实跨服务只读接入、一种写操作及状态查询/轮询/对账/人工处理，并写流程图。

本轮选择独立本地订单/支付业务服务和退款写操作。这里的“真实接入”指真实 HTTP 调用、独立数据库事务和持久化业务状态；数据为明确标记的合成数据，不涉及真实资金，不等同于接入银行、支付公司或承运商生产平台。其余评估缺口保持待办，不能据此宣称全面生产就绪。

实现与验收记录见 [业务接入说明与流程图](business-integration.md)。
