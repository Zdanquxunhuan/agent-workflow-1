# ADR-003：单文档版本发布与显式保留期回收

日期：2026-11-03。状态：V3 代码已开发，基础回归通过；既有数据迁移演练与生产验收未完成。

## 背景

V2 每个文档只处理首版，active_version_id 直接指向完整索引。生产更新需要在新版处理失败或耗时较长时继续服务旧版；引用必须指向原证据，并在权限撤销后停止读取。对象存储和 PostgreSQL 不共享事务，物理删除需要可恢复状态。

## 决策

本轮以文档为发布边界，保留现有数据结构。每次上传创建不可变 document_version，版本号在文档锁内分配。版本 lifecycle 与 ingestion job 状态分离：READY 只代表索引就绪，active_version_id 决定检索版本。内容变化使用独立 content_revision，ACL revision 不因发布而改变。

更新、发布、回滚、删除、回收按文档锁串行化。发布检查期望修订号、完整索引、当前模型 profile，并在同一数据库事务中切换 active 和写发布审计。并发冲突明确返回 409；自动发布冲突保留 READY 候选，不能静默覆盖。回滚是重新发布仍保留且曾经发布的版本，不恢复旧 ACL，也不能复活已删除文档。

手工发布要求 manager 及文档读取权。首版保持自动发布，新版默认人工发布，但 contributor 可以显式选择自动发布；自动发布继续检查当前写/读权限和提交时基准修订。当前不提供 KB 级强制审批策略，产品不能宣称已经实现职责分离审核。

引用固定 chunk/version。历史引用按当前权限返回旧内容并标记 historical；搜索仍只召回 active 版本，模型调用后按当前权限和 active 指针过滤，尚无整库一致性快照。草稿仅对当前有写权限的上传者和有文档读取权的 manager 可见。

回收先预览保留期、最近版本、hold、active、处理中任务保护，再由管理员显式排队为 PURGING。独立租户 GC 使用持久任务、租约和 fence；重复 S3 DELETE 幂等，数据库事务保存引用 tombstone、删除索引并标记 PURGED。PURGING 不可恢复为可读/可发布状态；默认 Compose 不启动 GC。对象删除成功后数据库提交失败依赖重复删除恢复，不能宣称跨 S3/PG 原子事务。

## 取舍与后续

单文档更新能够复用现有 Worker/检索过滤，代价是没有整库 manifest、跨文档原子发布和换模型影子重建。后续引入 generation 时，需要保留当前内容修订、实时权限和引用定位语义，处理重建期间增量更新水位。

当前 GC 只处理数据库中已经明确排队的版本，不处理孤立上传、S3 versioning 历史对象、备份删除传播或所有租户自动编排。版本元数据、发布审计和引用 tombstone 保留，后续需制定其保留与导出策略。

0003 迁移需要停止所有 V2 写服务，不能让旧 Worker 混跑；不提供破坏性 downgrade。代码/升级说明见 [V3 交付](version-3.md)，候选验收任务见 [测试交接](testing-v3-handoff.md)，已执行的基础回归见 [测试记录](verification-v3-2026-11-03.md)。工作库尚未升级。
