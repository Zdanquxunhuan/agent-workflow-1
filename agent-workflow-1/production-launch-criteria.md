# 上线判定标准与简历表述指南

> 结论先行：**完成 `ds-todolist.md` 不等于可以上生产；它最多把你从“演示原型”推进到“可试点候选”。**  
> “已上线生产系统”不是代码完成度，而是一个需要真实环境、真实用户、真实流量、运维责任和合规签字的事实陈述。  
> 关联文档：[ds-todolist.md](ds-todolist.md)、[docs/production-readiness.md](docs/production-readiness.md)

---

## 1. 为什么“完成清单”不等于“可以上生产”

### 1.1 清单是必要条件，不是充分条件

`ds-todolist.md` 里的 P0/P1/P2 是**工程就绪度**清单。全部完成只能证明：

- 代码层面补上了身份、持久化、并发、恢复、观测、审计等能力；
- 你有了一套可验证的工程证据。

但生产上线还额外要求：

- 真实下游系统接入和对方配合；
- 安全、合规、法务、数据保护评审；
- 真实用户/业务方验收；
- 值班、告警、事故处理、回滚和灾备；
- 容量、成本、SLO 和业务风险接受。

这些不是“写代码”能单独完成的。

### 1.2 清单里有些条目不是代码，而是组织证据

例如：

- “真实写工具具备业务幂等键、状态查询和人工对账”需要支付/订单/物流团队配合；
- “安全评审签字”需要安全团队；
- “DPA/数据驻留评估”需要法务和合规；
- “双实例、故障注入、压测通过”需要目标环境和真实依赖；
- “值班手册和 on-call”需要组织安排。

如果你只是在本地把这些复选框勾上，但没有真实系统、真实人员和真实演练，那不算完成。

### 1.3 生产是责任转移，不是功能完成

上线意味着：**出问题时有人负责、能回滚、能恢复、能对账、能赔付。**  
一个没有真实用户、没有监控、没有值班、没有回滚演练的系统，即使代码很漂亮，也只是 Demo。

### 1.4 当前项目仍然没有真实业务闭环

当前仓库的写工具是模拟的，知识库是本地词料检索，默认规划器是离线规则。  
即使把所有 P0 代码项补完，如果没有接入真实模型、真实只读系统和一个受控写操作，它仍然不是“生产系统”，而是“生产化改造后的原型”。

## 2. 先区分四个词

简历上最容易出的问题，是把这四个词混着用。

| 说法 | 含义 | 需要什么证据 | 个人项目能否使用 |
| --- | --- | --- | --- |
| **线上部署** | 服务部署在公网/云上，有 URL，能访问 | 部署记录、URL、基本监控 | 可以 |
| **生产环境** | 公司用于承载真实业务的环境，有变更/权限/审计流程 | 生产环境权限、发布记录、值班 | 通常只有在公司项目中可以 |
| **生产系统** | 承载真实用户、真实业务影响、有 SLA/运维责任的系统 | 真实用户/流量、SLO、on-call、事故记录、合规签字 | 个人项目很难严谨使用 |
| **生产级** | 按生产标准设计（安全、可观测、可恢复等） | 设计文档、测试、演练、评审证据 | 可以说“按生产标准设计”，不能说“已上线生产” |

**建议：**

- 个人项目部署到公网：写“**已部署上线**”或“**公网 Demo**”，不要写“生产系统”。
- 在公司真实环境上线：可以写“**已上线生产系统**”，但要能说清公司、系统、角色、规模、指标。
- 想表达工程质量：写“**按生产标准设计/完成生产化改造**”，并给出证据。

## 3. 五级就绪模型

用 L0–L4 描述项目阶段，比“完成/未完成”更准确。

### L0：本地演示原型

**特征**

- 本地运行，模拟数据，模拟写工具；
- 无真实模型或模型未验证；
- 无真实用户、无监控、无值班；
- 测试全部在内存模式。

**当前项目位置：L0+ / L1 代码候选。**  
已经有安全执行内核、MySQL 真实业务写入、JWT 认证、生产配置门禁和双实例验收；但真实模型、真实只读下游、监控值班和组织证据仍未完成。

**简历可以写**

- “个人项目 / 可运行原型 / Agent 安全执行内核”
- “实现服务端工具白名单、审批门禁、状态机、审计与幂等”
- “56 个自动化测试、73 项双实例验收检查、25 条评估样例”

**不能写**

- “已上线生产系统”
- “生产级高可用”
- “支撑真实业务”

---

### L1：内部受控试点

**入口条件**

- P0 全部关闭；
- 真实身份认证、租户隔离、职责分离；
- 真实模型可用，模型名/超时/成本可控；
- 生产化持久化（JDBC + 连接池 + 版本/幂等）；
- 任务租约/恢复正确，滚动发布不误伤；
- 真实或沙箱下游，至少一个只读工具；
- 基础可观测性、审计 Sink、回滚手册；
- 试点用户白名单，默认 fail closed；
- 明确“不产生真实资金/客户影响”或“可人工回滚”。

**特征**

- 内部员工/沙箱租户使用；
- 可能是只读，或单一低风险写操作；
- 有监控和人工兜底，但不承担公开 SLA。

**简历可以写**

- “完成生产化改造，进入内部受控试点”
- “在沙箱环境接入真实模型与只读业务系统”
- “试点期间 N 名用户、M 次请求，P95 延迟 X ms”

**不能写**

- “已上线生产系统”（除非公司正式定义该试点为生产）

---

### L2：小流量生产试点

**入口条件**

- L1 全部条件；
- 真实用户、真实流量、真实业务动作（可以是只读或单一低风险写）；
- allowlist 租户/操作灰度，可随时关闭；
- 24/7 监控、告警、值班、回滚；
- 完成压测、故障注入、数据库恢复演练；
- 安全/合规评审通过；
- 业务方接受风险和人工兜底流程；
- 有明确的 SLO 和事故处理流程。

**特征**

- 已承载真实业务影响，但范围受控；
- 有 on-call 和回滚能力；
- 可以称为“生产试点/小流量生产”，但仍不是全面 GA。

**简历可以写**

- “小流量生产试点”
- “服务 N 名真实用户 / M 次真实请求”
- “连续运行 X 天，可用性 Y%，处理 Z 次告警/故障”
- “接入真实订单/物流/支付沙箱，完成幂等与对账”

**谨慎写**

- “已上线生产系统”可以，但建议加限定词：“小流量生产试点”。
- 不要省略“试点/灰度/受限”这些事实。

---

### L3：正式生产 / GA

**入口条件**

- L2 全部条件 + 稳定运行周期（例如 30–90 天）；
- SLO 达标，错误预算可控；
- 容量/成本达标，压测覆盖峰值；
- 灾备恢复演练通过，RPO/RTO 达标；
- 安全、合规、法务、数据保护签字；
- 变更管理、发布回滚、事故复盘流程成熟；
- 有明确业务负责人和运维负责人；
- 真实用户/流量达到业务预期。

**特征**

- 真正意义上的“生产系统”；
- 出问题有组织级责任和赔付/补救能力。

**简历可以写**

- “已上线生产系统”
- “支撑 N 用户 / 日均 M 请求 / 峰值 QPS”
- “SLO 99.X%，P95 X ms，成本 Y 元/千次”
- “负责发布、监控、告警、故障处理和复盘”

**必须能回答**

- 生产拓扑是什么？
- 数据库/队列/模型供应商怎么部署？
- 监控和告警怎么配？
- 出过什么故障，怎么处理的？
- 如何回滚、如何对账、如何赔付？
- 安全/合规怎么过的？
- 你的角色和边界是什么？

答不上来，就不要写“已上线生产系统”。

## 4. 完成 `ds-todolist.md` 后你在哪一级？

| 完成情况 | 最多到达 | 说明 |
| --- | --- | --- |
| 只完成 P0 代码项，本地验证 | L0+ / L1 候选 | 有工程能力，但没有真实环境和组织证据 |
| P0 全部 + 真实模型 + 真实只读下游 + 沙箱试点 | L1 | 可以写“内部受控试点” |
| P0 + P1 + 真实用户/流量 + 监控值班 + 安全评审 | L2 | 可以写“小流量生产试点” |
| P0 + P1 + P2 + 稳定运行 + 合规签字 + 灾备 | L3 | 才可以严谨写“已上线生产系统” |

**关键点：**

- P0 是“上线阻断项”，不是“上线完成项”。
- P1 是“试点前必须”，P2 是“规模化完善”。
- 即使 P0/P1/P2 全部完成，如果没有真实用户、真实流量、值班和合规签字，仍然不是生产系统。

## 5. 写“已上线生产系统”的最低证据门槛

如果你要在简历上写这句话，至少要能拿出下面大部分证据。缺少关键项，就降级表述。

### 5.1 硬门槛

- [ ] 部署在真实生产环境（不是本地、不是个人 VPS 的演示环境）。
- [ ] 有真实用户（不是只给自己或几个朋友用）。
- [ ] 有真实业务流量（有请求量、并发、峰值）。
- [ ] 承载真实业务动作（至少一个真实只读系统；写操作需可回滚/可对账）。
- [ ] 连续稳定运行至少 30 天（建议 60–90 天）。
- [ ] 有监控、告警、值班和事故处理记录。
- [ ] 有发布/回滚流程，并实际演练过。
- [ ] 有安全评审和合规/数据保护签字。
- [ ] 有明确的业务负责人和运维负责人。
- [ ] 你能说清自己的角色、边界和关键决策。

### 5.2 证据材料

- 部署记录/发布单/变更记录；
- 监控看板截图（请求量、错误率、P95、饱和度）；
- 告警记录和一次真实故障复盘；
- 压测报告和容量结论；
- 数据库备份/恢复演练记录；
- 安全评审/渗透测试/合规评估结论；
- 用户量、请求量、SLO、成本数据；
- 回滚演练记录。

### 5.3 一句话判断

> 如果你不能在面试中拿出上面至少一半的证据，**不要写“已上线生产系统”**。  
> 写“已部署上线，服务 N 名真实用户”或“完成生产化改造，进入内部试点”更稳，也更有说服力。

## 6. 简历表述矩阵

### 6.1 当前阶段（L0+）

可以写：

> **企业售后 Agent 工作流（个人项目 / 可运行原型）**
> - 设计“模型只规划、服务端执行”的 Agent 架构：LLM 输出结构化计划，服务端强制工具白名单、参数校验、RBAC 与高风险审批门禁。
> - 实现任务状态机、幂等创建、重复审批保护、审计事件与 Outbox、只读 checkpoint 恢复；56 个自动化测试 + 73 项双实例验收检查 + 25 条评估样例通过。
> - 接入 DeepSeek OpenAI 兼容 Tool Calling，限制只读工具与最大回合，对模型输出做二次校验。
> - 基于 MySQL/Flyway 实现持久化适配，设计 Outbox 租约投递与失败重试；双实例验证唯一约束幂等、行锁审批、审批/取消竞争和过期任务恢复。

不要写：

- 已上线生产系统
- 生产级高可用
- 支撑真实业务/真实用户
- 高并发

### 6.2 完成 P0 后（L1 候选）

可以加：

> - 完成生产化改造：OIDC/JWT 身份、租户隔离、职责分离、HikariCP、乐观锁、任务租约、readiness/liveness、结构化日志与审计 Sink。
> - 在沙箱环境接入真实模型和只读业务系统，完成幂等、超时、重试和故障注入验证。

仍然不要写“已上线生产系统”，除非真的进入公司生产环境。

### 6.3 进入 L1 内部试点

可以写：

> - 完成内部受控试点：N 名试点用户、M 次请求，P95 延迟 X ms；接入真实只读订单/物流系统，默认 fail closed。
> - 建立监控、告警、审计和人工兜底流程，完成回滚与数据库恢复演练。

### 6.4 进入 L2 小流量生产试点

可以写：

> - 小流量生产试点：服务 N 名真实用户，日均 M 请求，连续运行 X 天，可用性 Y%。
> - 接入真实业务系统，完成业务幂等、未知副作用处理、对账和人工处理队列。
> - 建立 SLO、值班、告警和事故复盘机制，完成压测与灾备演练。

### 6.5 进入 L3 正式生产

可以写：

> - 已上线生产系统：支撑 N 用户 / 日均 M 请求 / 峰值 QPS，SLO 99.X%，P95 X ms。
> - 负责生产发布、监控、告警、故障处理和复盘；完成安全/合规评审与灾备演练。

**注意：** 只有在公司真实生产环境、有真实业务责任时，才建议使用 L3 表述。

## 7. 面试官会怎么追问

如果你写“已上线生产系统”，下面这些问题一定会被问：

- 生产环境部署在哪里？几台机器/几个实例？数据库/队列/模型怎么部署？
- 真实用户多少？日均请求多少？峰值 QPS 多少？
- SLO 是多少？P95/P99 延迟多少？错误率多少？
- 监控用什么？告警怎么配？谁值班？
- 出过什么故障？怎么定位、怎么回滚、怎么复盘？
- 写操作怎么保证幂等？未知副作用怎么处理？怎么对账？
- 安全怎么做的？身份、租户、审批、审计、密钥管理？
- 数据合规怎么过的？PII 怎么处理？模型供应商 DPA？
- 成本多少？模型 token 成本怎么控制？
- 你在项目中的角色是什么？哪些是你做的，哪些是别人做的？

**如果你答不上来，面试官会认为你在夸大。**  
反过来，如果你能拿出监控截图、故障复盘、压测报告和真实指标，这个项目会非常有说服力。

## 8. 从当前到“可辩护的线上表述”：6 周建议

### 第 1–2 周：先把 P0 做成真的

- 接入 OIDC/JWT，移除客户端角色头；
- 生产 profile 强制 JDBC，HikariCP，version 乐观锁；
- 修任务租约/恢复，滚动发布不误伤；
- 修模型名，接真实模型，做 PII 脱敏；
- readiness/liveness、结构化日志、指标、Trace；
- 真实审计 Sink + DLQ。

### 第 3–4 周：接真实系统和证据

- 接一个真实只读系统（订单/物流/工单任选）；
- 接一个沙箱写操作，完成幂等、状态查询、未知副作用、对账；
- 做压测、故障注入、数据库恢复演练；
- 写值班手册、回滚手册、事故复盘模板。

### 第 5–6 周：小流量试点

- 公网/内网部署，加认证、限流、配额；
- 找 5–20 名真实用户/同事试用；
- 连续运行 30 天，收集请求量、延迟、错误、成本、人工介入率；
- 处理至少一次真实告警/故障并复盘；
- 拿到安全/合规/业务方的书面确认（公司场景）。

完成后，你的简历可以写：

> “完成生产化改造并进入小流量试点：N 名真实用户、M 次请求、连续运行 X 天、P95 X ms、可用性 Y%；接入真实只读业务系统，建立监控、告警、对账和回滚机制。”

这比空写“已上线生产系统”更可信，也更容易在面试中展开。

## 9. 公司场景的上线签字清单

如果是公司项目，上线前至少需要这些角色确认：

- [ ] 工程负责人：代码、测试、发布、回滚
- [ ] 安全：身份、权限、密钥、漏洞、审计
- [ ] 合规/法务：数据保护、模型供应商 DPA、数据驻留
- [ ] 运维/SRE：容量、监控、告警、值班、灾备
- [ ] 业务负责人：流程、人工兜底、风险接受
- [ ] 数据负责人：数据质量、保留、删除、对账
- [ ] 客服/运营：培训、话术、升级路径

没有这些签字，即使代码全绿，也不能称为“生产系统”。

## 10. 最终建议

### 现在怎么写

写“个人项目 / 可运行原型 / Agent 安全执行内核”，重点写：

- 服务端执行控制（工具白名单、参数校验、RBAC、审批门禁）；
- 状态机、幂等、审计、Outbox、恢复；
- 56 个自动化测试、73 项双实例验收检查、25 条评估样例；
- DeepSeek Tool Calling、只读工具限制、输出二次校验；
- 生产化差距分析和 P0/P1/P2 规划。

### 什么时候升级表述

- 完成 P0 + 真实模型 + 真实只读系统 + 沙箱试点 → 写“内部受控试点”。
- 有真实用户/流量 + 监控值班 + 安全评审 → 写“小流量生产试点”。
- 稳定运行 + SLO + 灾备 + 合规签字 + 真实业务责任 → 才可以写“已上线生产系统”。

### 一句话

> **“完成清单”证明你能把系统做到可试点；“已上线生产系统”证明你在真实环境里承担过责任。前者靠代码，后者靠证据。**

> 企业售后 Agent 工作流（个人项目）：服务端主导的 Agent 执行内核，LLM 仅生成结构化计划，服务端执行工具白名单、参数校验、RBAC 与高风险审批门禁；实现状态机、幂等、审计、Outbox 和只读 checkpoint 恢复；56 个自动化测试、73 项双实例验收检查与 25 条评估样例通过。

**完成 P0 后**

> 完成 Agent 工作流生产化改造：OIDC/JWT 身份、租户隔离、职责分离、HikariCP、乐观锁、任务租约、readiness/liveness、结构化日志与审计 Sink；在沙箱环境接入真实模型与只读业务系统，完成故障注入和恢复演练。

**L1 试点后**

> 内部受控试点：N 名用户、M 次请求，接入真实只读订单/物流系统；建立监控、告警、审计和人工兜底，默认 fail closed，完成回滚与数据库恢复演练。

**L2 小流量生产后**

> 小流量生产试点：服务 N 名真实用户，日均 M 请求，连续运行 X 天，可用性 Y%，P95 X ms；完成业务幂等、未知副作用处理、对账和人工处理队列，建立 SLO、值班和事故复盘机制。

**L3 正式生产后**

> 已上线生产系统：支撑 N 用户 / 日均 M 请求 / 峰值 QPS，SLO 99.X%，P95 X ms；负责发布、监控、告警、故障处理和复盘，完成安全/合规评审与灾备演练。
